# 续航与功耗

电池只有 **520 mAh**（规格见上游 `docs/hardware-design/specifications.zh_CN.md`）。
上游仓库**没有提供任何实测电流数据**，它的 `demo_low_power.c` 只演示了 RTC 定时器
唤醒的 light/deep sleep，并明确写着"不使用按键唤醒：仓库尚无板级唤醒电路证据"。
所以下面的量级是按数据手册估的，**不是实测**；真实数字请用本文最后一节的方法测。

## 电流花在哪

| 消耗源 | 量级（估算） | 说明 |
| --- | --- | --- |
| **LCD 背光 @100%** | **20–60 mA** | 绝对大头 |
| CPU @160 MHz（射频关） | 20–25 mA | 已降到 80 MHz，省约 8–10 mA |
| LVGL port tick | — | `ESP_LVGL_PORT_INIT_CONFIG()` 默认 5 ms，每秒唤醒 200 次 |
| UI 定时器 | — | 原来固定 200 ms |
| 按键 ADC 轮询 | — | ~50 ms 一次 |
| ST7789 控制器 | 1–5 mA | 常开（当前不熄屏） |
| CW2017 电量计 | µA | 忽略 |
| ES8311 音频 | 0 | 本应用**从不初始化**音频 |

## 已经做了的

1. **背光空闲管理**（`main/otp_power.c`）——30 秒无按键后降到 10%。**不熄屏**：
   变暗之后仍然一眼能看清验证码，这正是这张卡的用法——抬眼扫一下，而不是先按键再看。
   按任意键恢复全亮，且**不吞这次按键**（屏幕本来就看得见，吞掉只会显得迟钝）。
   同步页例外，它始终全亮——屏幕上那个 `FoloPass-XXXX` 正是要在浏览器里认的。

   代价要说清楚：不熄屏意味着背光永远在耗电，省下的只是"全亮 → 10%"那一段。
   若哪天愿意接受熄屏，把这块改回去能再省一截，但按键唤醒的吞键行为要一并恢复。
2. **CPU 160 → 80 MHz**。ESP32-C3 的 APB 固定 80 MHz，SPI 屏的 40 MHz 时钟不受影响。
3. **刷新周期跟着屏幕状态走**：全亮 200 ms、变暗 1 s。变暗时仍照常刷新——
   屏幕还看得见，验证码不能是停住的。
4. Wi-Fi 只在开机对时的十几秒里存在，之后 `esp_wifi_deinit()`；BLE 只在同步页存在。

## 刻意没做 deep sleep

两个理由，都不是"嫌麻烦"：

1. **会毁掉 TOTP 的时间精度。** `CONFIG_RTC_CLK_SRC_INT_RC`——深睡期间靠内部 RC
   振荡器计时。ESP-IDF 会用晶振校准它，但仍有 0.1~1% 的误差，反复长睡会累积到秒级。
   而这个项目的立场是"宁可不显示，也不给一个看不出错的码"。
2. **按键唤醒不可靠。** 三键共用 GPIO0 的电阻分压，电压窗口是
   `{0,150} {150,447} {447,1900}` mV（`bsp_pins.h`），而 ESP32-C3 的数字低电平阈值
   约 0.8 V——**第三个键最高只到 1.9 V，压不出低电平**。"按任意键唤醒"实际只有
   两个键管用。上游那句"尚无板级唤醒电路证据"是有道理的。

下一步若要继续省，方向是 **DFS + 自动 light sleep**（`CONFIG_PM_ENABLE` +
tickless idle，并放宽 LVGL port 的 5 ms tick）。注意一个坑：**USB 控制台连着时会
持有 PM 锁，插着线永远不会进 light sleep**，只有拔线用电池时才生效——很容易被误判成
"改了没效果"。这一条应当在拿到实测基线之后再做。

## 能续航多久

### 估算（区间很宽，仅供对照）

上游没公布任何电流数据，背光的实际电流是最大的未知数，所以只能给量级：

| 场景 | 估算电流 | 520 mAh 对应 |
| --- | --- | --- |
| 正常佩戴（多数时间处于 10% 变暗） | 背光 2–6 + CPU@80 MHz 15–20 + 其余 3–8 ≈ **20–34 mA** | **15–26 小时** |
| 一直全亮 | 背光 20–60 + 其余 18–28 ≈ **38–88 mA** | **6–14 小时** |

区间宽到没法当结论用，**以实测为准**。

### 实测（约 20 分钟）

固件自带放电记录（`main/otp_batlog.c`），**下次开机时把上一轮的记录打到串口**——
因为真正的放电测试必须拔掉 USB 跑，而那时串口没人听。

能做到 20 分钟出结果，靠的是满精度的电量读数：CW2017 的 SOC 寄存器**低字节是
1/256 %**（0.004%），而上游 `bsp_battery_soc()` 只返回高字节的整数百分比。本仓库
给 BSP 补了 `bsp_battery_soc_q8()`。差别是实打实的：按整数百分比，10 小时的电池要
6 分钟才跳 1%，得跑几小时才有可信斜率；按 1/256 %，十几分钟就够。

记录规格：每分钟一个点，环形保留最近 144 点（2.4 小时），每 5 个点落一次盘
（每分钟重写 870 字节的 blob 太磨 flash，掉电最多丢 5 分钟数据）。

```
1. 充满电（顶栏电量到 100%），拔掉 USB。
2. 放着别动 20~30 分钟。中途别按键——按了就是在测全亮功耗。
3. 插回 USB，复位一次，接串口看启动日志。
```

输出形如：

```
uptime_min,soc_percent,mv
0,98.44,4131
1,98.05,4118
...
===== 22 分钟掉 1.95%；平均 27.6 mA；按 520 mAh 线性外推满电约 18.8 小时 =====
```

想知道背光到底吃多少，就再跑一轮，中途每十几秒按一下键让它保持全亮，两条斜率一减
就是背光那一段。

**不要拿插着 USB 的运行时长当续航**——那时它在充电，SOC 只会上升，
设备会直接打印"电量没有下降（多半是插着 USB 在充电），无法估算"。
