# 威胁模型与已接受的取舍

这套东西的本质是：把 TOTP 种子从手机复制到**浏览器**和**一张挂在胸前的卡**上。
这会削弱"第二个因素"原本依赖的分离性。下面把每一处削弱、当前的挡法与代价写清楚，
不做"已加密所以安全"的含糊表述。

## 三处存放与传输

### 1. 浏览器（`web/`）

- 条目在 IndexedDB 中以 AES-GCM 密文存放，包裹密钥以 `extractable: false` 生成。
- **挡得住**：离线翻取浏览器数据目录的人。
- **挡不住**：同源上的 XSS（能直接调 `crypto.subtle.decrypt`）、正在操作你已解锁浏览器的人。
- 运行时不发起任何网络请求：无遥测、无远程字体图标、不校时。CSP 不含
  `unsafe-inline` / `unsafe-eval`。
- **单文件形态（`file://`）没有来源隔离**：同一浏览器打开的任意本地 HTML 都能读到这份
  保险库并解密。细节见 [`../web/README.md`](../web/README.md)。此外 `file://` 不是安全上下文，
  Web Bluetooth 与 WebCrypto 都用不了——单文件版**不能**用来同步工卡。

### 2. 工卡（NVS）

- 种子**明文**存在 NVS 的 `folo2fa/vault` 里。没有 PIN、没有锁屏，开机即显示验证码。
- **挡不住**：捡到卡的人（能看到全部验证码）、能物理读取 flash 的人（能拿到全部种子）。
- 这是本项目当前明确选定的取舍：工卡的输入只有三个按键，加一层 PIN 会把"抬手就看"
  变成"每次开机敲六下"。若要改，方向见下文「可选的加固」。

### 3. BLE 链路

- 链路**不加密、不配对**，同步的那十几秒内明文种子在空中。
- **挡在数据前面的是物理动作**：BLE 协议栈只在工卡停留在 SYNC 页面时启动并广播，
  退出页面立即 `nimble_port_stop()`。也就是说，要推数据进这张卡，必须有人拿着它按键。
- **代价**：射频范围内的嗅探设备能在同步窗口内看到明文种子。
  **请在家里或自己工位上同步，不要在会场、机场这类地方推。**
- 为什么不用 BLE 配对加密：Just Works 配对不抗中间人，只是把嗅探门槛抬高一点；
  带 passkey 的配对在 Chrome + macOS/Windows 上的体验与可靠性差异很大，
  而本项目的其余取舍（明文 NVS）已经决定了威胁模型的量级——加一层不牢靠的配对
  会造成"已经加密了"的错觉。

### 4. Wi-Fi（开机对时）

配置了 Wi-Fi 凭据之后，工卡每次开机会联网做一次 SNTP 对时，然后 `esp_wifi_deinit()`
把协议栈整个拆掉。这带来三处新的暴露面：

- **凭据明文**：SSID 与密码经不加密的 BLE 链路下发（同步窗口内可被嗅探），并明文存在
  工卡的 NVS 里。捡到卡的人能拿到你的 Wi-Fi 密码。**别用主网络的密码，给它一个访客网络。**
- **开机十几秒内设备在联网**：这段时间里它有 IP、有完整的 lwip 协议栈。虽然不开任何监听
  端口，但攻击面确实比"永远不联网"大。连接与对时各有超时（12 秒 / 10 秒），失败即关闭。
- **NTP 没有认证**：能控制你网络的人可以把工卡的时间拨走，验证码随之全错。这**不会泄露
  种子**，代价是"码不对"而不是"码被偷"。真要防，只能上 NTS 或改回手动对时。

不配 Wi-Fi 时以上三条都不存在，代价是每次掉电后都要靠网页对一次时。

## 已经做到的几条

- **推送是整体替换，且只有 COMMIT 成功才生效**：中途断链不会在卡上留下半份保险库。
- **没有可信时间就不显示验证码**：冷启动后工卡只显示 `NO TIME`。显示一个看不出错的
  错码，比不显示更糟。
- **种子在内存里用完即抹**：BLE 会话缓冲、NVS 序列化缓冲、HMAC 摘要在用完后 `memset`。
- **网页不认识密钥的明文用途之外的任何东西**：不上传、不同步、不打点。

## 可选的加固（当前**未实现**）

按代价从低到高：

0. **给工卡单独一个访客 Wi-Fi**：这条不用改代码，是当前配置下最划算的一步。
1. **工卡 PIN**：以三键序列（如 6 位「上/下/确定」）派生密钥加密 NVS 里的种子，
   开机需输入。代价是每次开机多几秒，且忘记 PIN 即等于丢卡。
2. **同步二次确认**：COMMIT 前在工卡上显示"接受 N 条？"，需按键确认。
   挡的是"有人趁你把卡放在桌上时推一批假种子进去"。
3. **应用层加密链路**：在协议里加一层由用户在两端各输入一次的短口令派生的密钥。
   比 BLE 配对可控，但要在三个按键上输口令，体验代价与 PIN 相当。
4. **只在内存里保存**：关机即忘，每次开机重新同步。安全性最高，日常最难用。

这些都会改变 [`protocol.zh_CN.md`](protocol.zh_CN.md) 的契约，属于需要先确认再动手的改动。
